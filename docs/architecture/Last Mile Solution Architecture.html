Last Mile: from a bank's risk prediction to an approved collections action

Banks send data over their own APIs. Eight agents run a fixed daily pipeline on top of deterministic maths, a person approves every action, and an LLM is used in exactly two places — never for a number, never with customer data.

A business day, end to end

  1. The manager confirms today's team and starts the run.
  2. Ingestion pulls six feeds from the bank; Configuration applies the rules and roster.
  3. Data Steward runs 13 quality gates and moves personal data to the vault.
  4. Feature turns grades or probabilities into default risk and builds model data.
  5. Decision scores uplift, asks Policy what is allowed, optimises and fits each collector's shift.
  6. Policy re-verifies the plan and audits it; Explanation writes checked reasons.
  7. The manager approves, releases to the bank, and closes the day.

Where AI is used — and where it is not

  • ① LLM Explanation wording: it sees segment × action pairs, writes templates with placeholders; figures are filled from sourced facts.
  • ② LLM Onboarding a bank: it sees column shapes and ranges, proposes endpoints, mapping and score type; checks and an admin decide.
  • Everything else — model, dollar values, optimisation, simulation, rules, audit — is deterministic code: same input, same output.

Boundaries that protect members

  • Sign-in gate on every page and API call; guests cannot change anything.
  • Identity vault: models and the LLM work on tokens; names return only to write the call script at release.
  • Rules run twice: before planning (fail-closed) and after (independent verification).
  • Human approval before any action reaches the bank; every decision is in the hash-chained audit.
