Hackfest'26 · Last Mile · Solution architecture

From a prediction the bank already has, to an action a person approved

Five stages. The decision in the middle is the part a sorted list cannot do, and a person stands between every recommendation and every customer.

our model a rule, or a person the language model — two jobs, both wording deterministic code

Where each part of this is load-bearing

Component design and integration

Each stage is a separate layer with one job, and the boundaries are enforced in CI rather than by convention. Two banks run on this engine today with no code difference between them — different API paths, different column names, and one sends grade bands while the other sends a 180-day probability.

Extensibility

A new bank is a configuration pack, proposed by an onboarding agent and approved by an admin. A new decision — NPA early warning on commercial loans — is written against the same schema and validates; it has not been run, because that needs a loan feed we do not have.

Security and governance

Personal data goes into a vault at stage 2 and is read again only to write a call script at release. Three roles are checked on every request. Every decision is in a hash-chained audit, and the rules run twice — before the solver, and again on the finished plan.

Responsible AI and human-in-the-loop

The language model appears once, to write wording, and is checked against the facts it was given. It produces no number and takes no decision. Every recommendation carries a reason with a source for each figure, and nothing reaches a customer without a person releasing it.
